Core Principles

The Four Pillars of Relay Sovereignty

Architectural rules hardcoded into the foundation of Relay's codebase.

1. Zero Network Sockets

Relay does not open HTTP, WebSocket, or gRPC connections during task execution. The model inference loop runs entirely through embedded C++ LiteRT-LM bindings mapped to your local Silicon hardware.

2. Scoped Permission Boundaries

Unlike legacy desktop agents that demand unrestricted disk access, Relay operates through macOS security-scoped bookmarks. Relay can only inspect or modify the explicit folders you grant.

3. Open Markdown Storage

Your agent memories, task outputs, and logs are stored in standard human-readable Markdown. There are no proprietary binary databases, no hidden sync servers, and no platform lock-in.

4. Cryptographically Verified Weights

The Gemma 4 E2B `.litertlm` package is verified against an immutable SHA-256 hash before loading into memory. Relay rejects any modified or unverified model binaries.

Don't Take Our Word For It

Verify Air-Gapped Execution Yourself

True security is verifiable. Use standard macOS UNIX inspection tools to confirm that Relay maintains zero open network connections during multi-agent task execution.

1. Verify Open Network Sockets with lsof

While Relay is running a multi-agent task, query macOS network file descriptors for the Relay process ID:

# Check all internet/network sockets attached to Relay
$ lsof -p $(pgrep Relay) -i
[Expected Result: Exit code 0, 0 open sockets returned]

2. Audit Network State with netstat

Confirm zero TCP or UDP connection states associated with the application:

# Verify zero ESTABLISHED or SYN_SENT connection states
$ netstat -anv | grep -i relay
[Expected Result: Empty output]

3. Compatible with Application Firewalls

Relay operates seamlessly under third-party macOS application firewalls such as Little Snitch or LuLu. You can configure a strict rule blocking all network traffic for Relay; the multi-agent system and Gemma inference will continue operating at full speed.
