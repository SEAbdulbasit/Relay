# Full surface inventory and onboarding follow-up

This supplements the v4 audit and v4–v6 refinement reports. The user requested a checkpoint commit/push and a check of all pages, including onboarding. This pass adds an audit, not another unreviewed redesign. The dashboard remains the accepted reference.

## Remaining material findings

1. **P2 — Onboarding teaches a visually different Sidekick.** The native Instant Draft step renders a blue/purple nested HUD with app tabs, tone pills, attachment badges, multiple footer actions and shadows. The real Sidekick now uses a quiet dark shell and faint teal tint. `OnboardingMagicReplyDemoView.swift` and the Instant Draft composition in `OnboardingView.swift` should reuse the live control vocabulary and disclose secondary demo controls progressively. Keep the fictional-data boundary visible. Its “Instant Draft” name also differs from the real “Magic Reply” control; teach that relationship explicitly.
2. **P2 — Model and source setup still use the earlier panel hierarchy.** The native AI Engine step has a pill provider strip, provider panel, nested routing-example panel and colored diagram tiles. Memory Vault has a prominent launch banner above another source-selection panel, with multiple source badges and footer tools. `OnboardingView.swift` should flatten redundant panel layers and apply the newer neutral section symbols. Preserve selected state, account routing, source scope and permission explanations. Welcome's larger hero and calculator result are intentional introductory roles, not defects merely because they exceed page-title sizes.
3. **P2 — Onboarding Background Indexing dialog is a distinct design generation.** Native inspection confirmed a 24 pt-style title, large purple/green icon tiles, boxed rows and glowing pill-shaped “Start Indexing & Launch Relay” beside a standard rounded Close control (`OnboardingView.swift:2614–2755`). Apply the compact-dialog hierarchy and existing shared button styles. Do not change indexing, scheduling or login-item behavior as part of a visual correction.
4. **P2 — Source status copy needs an authority check.** Memory Vault shows “Selected · Permission required” for Apple Mail whenever it is enabled (`OnboardingView.swift:2041`). This is a hardcoded selection-dependent string, not a permission probe. Verify it against the actual source readiness authority and separate selected status from permission status. This audit does not claim that Mail permission is granted merely because unrelated capabilities are granted.
5. **P3 — Conditional utilities retain some older type roles.** Consolidation's title uses `.relayTitle`; the enlarged visual-review sheet uses `.relayHeadline`; private/archive questions and ephemeral text-action panels retain legacy caption/body variants. Review each in its actual role before replacing sizes. Native system menus/file panels and hardware-notch illustrations remain deliberate exceptions.

No new P1 issue was established by this pass. That does not certify all conditional states or all appearances.
