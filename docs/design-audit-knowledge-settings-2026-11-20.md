# Relay design audit: Knowledge, settings, and preparation

20 November 2026. Independent source audit of the current dirty checkout; no source changes in this lane. Root owns live UI review. Line references below describe the pre-redesign source. Existing reliability work is preserved. Optional design skills were not used.

## Design judgment

Relay's knowledge should feel like a personal research desk: material on the left, a beautifully readable document in the center, clear evidence of where it came from, and one obvious next action. Today it exposes the architecture: graph nodes/edges, source buckets, synthesis engines, separate index controls, and multiple background schedulers. A redesign should make the relationship **sources → useful notes → useful work** visible. Real content should create its personality; decorative simulated knowledge should not.

## Proposed visual direction: The Research Desk

A warm neutral document canvas with confident ink typography and one crisp cool accent for action. Left rail uses thin separators and collection counts; the document uses generous leading and a bounded text measure, not a nested elevated card inside another canvas. An editorial masthead (“Your knowledge” / “Keep the useful parts close”) gives the surface identity. Small provenance labels (“Your note”, “Generated from sources”, “Imported excerpt”) make the material's status immediately legible. Activity remains the place for operational detail. The constellation is a deliberate alternate exploration mode, not the primary organizational metaphor.

The outstanding detail should be the handoff: open a real note, understand where it came from, ask a question about it, and return to that note with context intact. No fabricated recent work, AI conclusions, timestamps, freshness claims, or source titles should be invented to fill a screen.

## Self-contained implementation boundary

Recommended immediate lane: `Sources/Relay/KnowledgeView.swift` only. Add a real Overview desk based on existing in-memory notes/records/graph; quieter header with one primary action and More menu; readable reader header/action placement; simpler sidebar and honest filter empty state. Retain `KnowledgeNavigationGuard`, exact node URL routing, source revalidation, Save/Discard/Cancel behavior, existing sharing/editor sheets, original accessibility IDs wherever controls remain, and all permission/ingestion/generation boundaries. No new persistence is necessary. No source refresh, model request, or synthesis should occur merely by rendering the new design.

A second, small independent change can remove the duplicate Run Analysis Cycle Now block from SettingsView and replace jargon in its suggestions header, leaving the actual manual control in PluggedInAnalysisScheduleView. A full scheduler readiness summary needs a shared presentation model, and passage-search results need route/async work; both should be treated as product work rather than simulated in a visual refresh.

## Implemented design iteration

The coordinator assigned this lane Knowledge only. Changes are in `KnowledgeView.swift` and new pure presentation `KnowledgeDeskOverview.swift`:

- A real research-desk Overview renders existing editable notes, current generated highlights, unique source count and nonempty graph collections. There are no invented timestamps or recent-work claims: local editable notes do not expose modification dates. Existing user-created Overview.md continues to open as an editable document.
- Notes/folders come before imported sources in the sidebar. Sources begin collapsed; choosing Browse sources expands their actual group. Collections use the existing graph URL, and rows use the same guarded node selection.
- A single New note action is prominent. Refresh, folder creation, writing style and sharing remain functional in Library actions. Constellation remains an explicit alternate mode.
- All six filters are visible in a three-column layout rather than a horizontally clipped chip row. No-match feedback can clear both text and domain filter. Synthesis/highlight controls remain available under Create from sources.
- Documents have type provenance, an editorial title, a separate action row, and an uncluttered reading canvas. Delete moves into Note actions. Note details replaces the implementation-oriented Move / Sheet label while retaining its existing save guard and editor sheet.
- Existing source admission, source freshness checks, permission boundaries, synthesis/ingestion, saved-note identity, deep links, sharing and Save/Discard/Cancel ownership are unchanged. Selected sidebar rows expose the selected accessibility trait; source group expansion respects reduced motion.

Swift frontend parser validation passed for both files, and scoped `git diff --check` passed. Root owns integrated compile and live verification. Settings and source-preparation changes remain recommendations, including the duplicate manual scheduler control. Passage retrieval and quit/crash draft recovery are outstanding product capabilities, not simulated by this redesign.
