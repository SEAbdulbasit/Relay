# Sentient OS feature parity plan

Prepared 7 November 2026. This is the implementation and acceptance plan, not a completion claim. **Relay has not reached full feature parity or fully qualified autonomous Mac control.** Existing tests, newly landed code and a successful primitive are different evidence from a completed user workflow.

## Fixed comparison baseline

- Installed reference: **Sentient OS 2.8 (24)**, as observed in the installed app during this review.
- Public implementation baseline: [`6214cc8b6bf30769f2af2272273931c41d14e744`](https://github.com/Sentient-OS-Labs/sentient-os/commit/6214cc8b6bf30769f2af2272273931c41d14e744), “Publish Sentient OS 2.8 source update.” The reference checkout is `.build/reference/sentient`; it is detached at that commit. The 2.8 tag points to an earlier source update and is not the baseline used here.
- The installed binary and the public source are **not assumed identical**. Record a binary observation separately from a source-documented behavior. Newer reference releases require a new inventory and an explicit baseline change.
- [The reference feature map](https://github.com/Sentient-OS-Labs/sentient-os/blob/6214cc8b6bf30769f2af2272273931c41d14e744/Sentient%20OS%20macOS/Documentation%20-%20General%20-%20README.md) and all 36 feature documents are covered by the source index at the end of this plan. Implementation details are checked against the associated entry points, not inferred from marketing screenshots.

## Product contract

**No Relay account, Relay login, subscription gate or mandatory hosted inference is required.** Local operation remains a complete supported path. Existing optional ChatGPT, Claude, email, calendar and connector accounts belong to their providers; those are not Relay accounts. Do not remove a source, provider or action merely because its integration or qualification is difficult.

Parity means equivalent user outcomes, lifecycle, recovery and visibility. It does not require reusing Sentient branding, credentials, infrastructure, private APIs or source code. Relay's original logo and visual identity remain its own. Reference-specific invitations, lifetime redemption and paid-plan marketing become an account-free access contract rather than a new Relay entitlement system. Optional support contact or report uploads need their own disclosed destination and consent.

The reference exposes knowledge to ChatGPT/Claude on phones through hosted MCP. Its pinned source does **not** establish a native Sentient iOS companion. A separate Relay iOS app is an optional enhancement, not a hidden prerequisite for this baseline.

The user asked for a simple, consistent interface with proper spacing and visibility. Every implementation below must use shared controls, predictable placement, legible states and clear errors. Adding settings, cards or capabilities is not permission to add decorative complexity or claim unsupported success.

## Status and evidence rules

| Status | Meaning |
|---|---|
| Missing | No equivalent supported user flow is implemented. |
| Partial | Some primitives or a narrower flow exist; listed behavior is still incomplete. |
| Implemented | The defined behavior has an implementation, but its final product acceptance is not yet closed. |
| E2E verified | The row's acceptance passed on the recorded frozen build, with independent outcome evidence and all relevant qualification gates closed. |

The initial matrix deliberately does not promote source presence or old unit tests to **E2E verified**. `C` in evidence means reviewed Relay code; `B` means earlier, explicitly scoped qualification described in [parity-status.md](parity-status.md); `I` means current iteration code awaiting final qualification. No percentage is inferred from file counts or test totals. A row can close only when its evidence records the build/revision, provider/model, permission state, test inputs, independent outcome and cleanup.

The follow-up default regression in `.build/verification/followup-frozen-default-swift.log` recorded **966 registered declarations: 904 executed/passed and 62 opt-in skips, 159 suites, 20.093 seconds**. The same strict current-schema native workflow passed on actual Gemma 4 E4B GPU (55.767 s) and E2B CPU (82.501 s), with exact Unicode input, one complete-form review, one independent Apply/result and unchanged unrelated draft. Production TextEdit capture/coordinator plus actual E2B summary also passed. Release packaging, strict deep ad hoc signature and constrained-size UI/local chat were observed. See [the follow-up verification record](verification-2026-11-07-followup.md), including retained failures and the final presentation check. Earlier evidence remains in [the previous milestone record](verification-2026-11-07.md). These checks do not close all rows, the packaged app's missing Accessibility grant or physical/service/signing gates. The ordinary planner still has no integrated general visual action loop; ignored controller/provider drafts are not product features.

Workstream owners: **AUT** autonomous control and execution; **CTX** conversation/context; **SRC** source ingestion and privacy; **KNW** knowledge/drafting; **QAC** summaries/proofreading/voice routing; **CON** providers/connectors/sharing; **SYS** scheduling/permissions/distribution; **UX** design/accessibility; **QA** integrated acceptance. Root coordinates dependencies and owns the final integration/push. These are work allocations, not claims that an agent is currently running.

## Ordered execution plan

1. **Freeze this inventory and acceptance contract.** Resolve any ambiguous reference behavior against the pinned source and installed app. Preserve the user's unrelated work and existing conversation, grants and preferences. Assign each open row to a workstream; do not replace this matrix with a smaller list of easy tasks.
2. **Make the core autonomous loop reliable first.** Close AUT-01 through AUT-08 and CTX-05 through CTX-09: context capacity, fresh references, bounded recovery, exact outcome evidence, Stop/drain and replay prevention. The real local-model native workflow must pass unchanged outcome assertions before broadening capabilities.
3. **Qualify the landed source/lifecycle fixes.** QAC-02, PFR-01 and VOI-07 now have scoped implementation and synthetic regression evidence below. Complete their packaged-browser, source-permission and microphone/session acceptance. Global invocation must bind the original source; an automatic voice quick action must not fail because opening its UI starts redundant preparation; session deactivation must stop voice and clear ephemeral readers.
4. **Complete source admission and ingestion.** Implement every SRC row, then TRI privacy/checkpoint rows. Add only explicit source scopes. Use synthetic databases and accounts first, then separately qualify existing live accounts. A completed empty read and a failed read must remain different states.
5. **Complete knowledge and Double Tap.** Close KNW and DTP rows, including semantic updates, edit-safe staging, provenance, writing-example snapshots and grounded replies. Do not substitute quoted highlights for a full semantic knowledge pipeline.
6. **Complete quick actions and conversation capture.** Close QAC, SUM and PFR rows for supported native/browser/chat/PDF/video/image flows, independent requests, retries, focus and Undo. Retain a complete local route.
7. **Complete providers, connectors and sharing.** Close MOD, CON and SHR rows across all supported backend choices and account generations. No provider credential is copied to another endpoint. No Relay login is introduced.
8. **Complete proactive preparation and long tasks.** Close PRO, CTX and remaining AUT rows: read-only live research, full reviewed artifacts, durable handoff, history retrieval and continued autonomous execution. Preparation does not silently send or publish.
9. **Complete managed overnight behavior.** Close OVR rows with fault injection first and physical power qualification separately. A previewed command is not a managed recurring wake service.
10. **Finish design and system operations.** Close UX, VOI, SYS and REL rows at normal and constrained sizes, with Reduce Motion, keyboard and accessibility checks. Complete reset, uninstall, diagnostics and signed update/rollback paths.
11. **Run the complete acceptance matrix on the frozen product.** Use the production app and task loop, actual supported models, isolated synthetic native/web targets and independent oracles. Then qualify the explicitly permitted real service and physical hardware rows. Repair failures and rerun affected rows plus the integration gates.
12. **Push only a reviewable, verified milestone.** Record the exact remaining open rows if a credential/hardware/signing gate cannot be exercised. Do not describe a milestone push as “100% parity.” The final full-parity claim requires every required row to be E2E verified, no unresolved blockers, and an observed working release installation.

## Required integrated acceptance packs

These packs complement, rather than replace, each row's acceptance:

1. **Account-free clean install:** no Relay login; local model download/import/probe; Home, notch, notes, sources and help; all no-grant/denied/unknown states; quit/relaunch and update migration.
2. **Production autonomous task:** real supported local model and optional existing providers; owned native form and isolated browser profiles; observe → edit → observe → review → one final action → observe; exact Unicode, stale refs, changed target, user activity, Stop and parent death. The app's evidence must distinguish actual goal completion from a click receipt.
3. **Multi-app/browser journey:** safe synthetic document → source-backed form fields → native selection/attachment → reviewed result; cold browser, redirects, selected-account change, popup/iframe/shadow content, focus conflict and unsupported controls.
4. **Source/knowledge journey:** opt in independent sources → interrupted backfill/incremental update → privacy/attribution checks → semantic knowledge build → edit-safe update → search/graph/citation → revoke → no stale inference. Repeat with each source and mixed-source failures.
5. **Quick actions:** typed, spoken, global and notch entry; original source capture; concurrent readers; PDF/native/browser/chat/video/image inputs; strict proofreading; replacement/readback/Undo/copy fallback; late response, window close, Stop, sleep and session lock.
6. **Grounded drafting:** selected real-like synthetic conversation and facts/style → exact unsent reply insertion; unsupported facts, protected data, irrelevant notes, source/field drift, clipboard ownership, cancellation and existing draft preservation.
7. **Proactive journey:** judge → read-only verification → full editable artifact → durable card reply → same main agent → exact account/source check → completed result/retirement; failed/uncertain/Stop paths preserve reviewed work.
8. **Unattended preparation:** durable schedule, DST/timezone, source/model availability, battery/thermal decisions, crash/heartbeat/deadman, cleanup, closed lid and actual morning result. Hardware results must be recorded per machine/power mode.
9. **Sharing/connectors:** local and hosted protocols, separate account generations, OAuth/PKCE/Keychain/rotation, disconnect/revocation, hostile replies, offline/retry, phone AI retrieval and no unintended credential/content transfer.
10. **Design/release:** every visible state at constrained/normal sizes and all display modes; keyboard/VoiceOver/Reduce Motion/low power; no clipping, hidden hit targets, accidental focus capture, unexplained busy state or unresponsive Stop; signed install/update/reset/uninstall on a clean supported Mac.

## Evidence record and closure procedure

Store durable verification artifacts under `.build/verification/` or an explicitly selected local test-artifact directory; temporary `/tmp` paths alone are not the release record. Do not commit personal source content, tokens, account identities or test dumps. A shareable record may contain a sanitized manifest and references to privately held artifacts.

Each row's closure record must contain:

- Row ID, exact scenario/fixtures, frozen commit or source digest, build type/bundle identity, macOS/hardware/display topology.
- Model/provider/runtime versions, existing grants and service-account scope, without credentials or private identifiers.
- Actual command/harness or manual steps, assertions, independent oracle/readback, measured result and cleanup.
- Positive, refusal, drift/cancellation and retry/relaunch coverage where relevant; unresolved limitations remain explicit.
- Reviewer and last verified date. A source change reopens affected rows and their integration dependencies.

**Full parity release gate:** every required row is E2E verified on the final integrated product, every applicable G0–G7 qualification is closed, all reported blockers are fixed, the complete acceptance packs pass, and the pushed revision matches the installed/packaged release. Merely compiling, passing a large unit-test total, using a trusted test host, or filling every implementation cell cannot satisfy this gate.
