## Implemented behavior

- Precise-window recovery now retains actual native object identity with `CFEqual`, process/launch/path/window/document binding, one-use read receipts and versioned error state. A successful read cannot erase a mutation error, a newer error or another operation's failure. Unbound helper references never acquire native authority by matching a label.
- Browser window-only observations avoid document traversal. A requested original window is checked before URL/toolbar metadata reads, including when multiple Chrome profiles run.
- Expiry handles controls whose enabled state is unknown while preserving fresh snapshot bytes, literal text and exact historical arguments. A bounded factual current-task ledger records protocol outcomes for the completion check. Assistant narration does not become evidence of execution; omitted calls and overlapping IDs do not become verified effects.
- The desktop helper's non-ASCII text path is refused before dispatch because a deterministic live fixture exposed Unicode decomposition and unverified text state. Relay directs a fresh native observation and exact native reference instead. Native Unicode/multiline entry remains supported. No normalization, Return, implicit second write or weakened outcome assertion was introduced.
- Current-document summaries route to Chrome/Safari, TextEdit or Preview. Native PDF metadata alone requires explicit PDF selection. Read-only, transient captures bind the original process/window/document, exclude protected/hidden/editable/chrome content and retain declared coverage. Unused native `AXDescription` is no longer fetched.
- Native conversation grouping has six structural profiles, but production whole-conversation admission remains conditional: only a declared Claude transcript with validated app-provided UUID document metadata, retained transcript identity and pre/post header checks can proceed. Unsupported or unprovable conversation identities offer selection fallback. No personal chat was inspected for this qualification.
- A transient native vision planning API prepares bounded JPEG input, original dimensions/hash and exact coordinate transforms. Local inference switches between separate text and vision runtime signatures. Images remain outside Codable history, tool feedback, saved state and hosted planners. **The ordinary task planner does not yet call this API.**
- Conversation typography, insets and maximum widths are shared. Action evidence and raw review details use quiet disclosures; Activity has less visual nesting. Incomplete results expose Inspect activity and Continue. Sidekick identifies an included source window clearly, and text actions advertise the applicable page/document/chat route.

## Reproduction

Run the default Swift regression with opt-in `RELAY_*` environment variables unset, then `python3 -m unittest discover -s Scripts/Tests`, `python3 e2e_tests/runner.py`, and `bash Scripts/build-app.sh release`. The default run intentionally does not launch a native app, model, microphone or service account. Native/model tests require the existing test-host macOS grants, a coordinated desktop slot and an already available local model; they must not substitute a permission grant or download for an unavailable qualification gate.

The actual strict workflow uses `NativeModelWorkflowIntegrationTests.actualGemmaFillsAndReviewsOneInertNativeFormWithIndependentOutcomeOracle` with `RELAY_RUN_NATIVE_MODEL_TEST=1`, the exact `RELAY_GEMMA_MODEL_PATH`, `RELAY_GEMMA_TEST_BACKEND` (`cpu`/`gpu`) and model label. TextEdit uses `RELAY_RUN_NATIVE_TEXTEDIT_SUMMARY_TEST=1`; scoped helper/native readback uses `RELAY_RUN_SCOPED_READBACK_TEST=1`. The transient canvas vision gate uses `RELAY_NATIVE_VISION_MODEL_PATH`. Run those suites sequentially, preserve failed logs and confirm owned-process cleanup before another app or model owns the desktop.
