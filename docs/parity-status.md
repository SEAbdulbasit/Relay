# Sentient OS parity status

Reviewed 7 November 2026. **Relay does not yet have full Sentient OS parity.** No Relay account is required. Local features use on-device inference; the optional ChatGPT workspace mode uses the user's existing Codex CLI sign-in and separate sharing reviews.

The installed comparison app reports Sentient OS **2.8 (24)**. Its [official 2.8 release notes](https://github.com/Sentient-OS-Labs/sentient-os/releases/tag/2.8) extend the earlier comparison baseline. Public source and the installed binary are not assumed identical. Source inspection, synthetic tests and live desktop qualification are different forms of evidence.

## Current implementation batch

- Reviewed plain-text Apple Mail drafts and sends using the existing Mail account. Each write requires an exact displayed approval. Sending rechecks sender, To/Cc/Bcc, subject, body, attachment state and approval expiry. Automatic Cc/Bcc settings refuse. Uncertain submission cannot be automatically replayed. Mail acceptance is distinct from recipient delivery. These paths are qualified with synthetic transports, not a live mailbox.
- Opt-in refresh of the original selected Notes and Mail items while Relay runs. The scope remains at most eight selected items per source, excludes locked items, and expires when the original source process changes. Session content and the refresh preference are not persisted.
- Exact dropdown values are forwarded to the desktop helper. The native adapter supports named, non-consequential AppKit `AXPopUpButton` controls with at most 64 inspected menu items and one exact, enabled choice. Independent live fixture readback covers Unicode, stale reviews and absent/duplicate/disabled choices. This does not qualify arbitrary dropdowns or consequential form submission.
- Selected-text summaries and proofreading use tool-free local inference in a temporary result window. Native proofreading shows both versions, binds an exact selection and full field, dispatches at most one replacement, and checks the complete resulting field. Browser fields, changed targets and unsupported formatting use copy-only output. Closing or Stop clears the session; selected text and results do not enter chat history or saved state. Live synthetic editors qualify the replacement adapter. A separate real Gemma 4 E2B CPU check passed exact spelling correction while preserving a blank paragraph, accented text and emoji (4.809 seconds), without dispatching an edit. An explicit no-Markdown/no-fences prompt fixed the observed response-wrapping failure; the complete, single-key JSON parser remains strict. This one example does not establish general proofreading quality.
- Browser selection uses the intended foreground process when several profiles are running. Cold startup waits for a native window before address entry. Unsupported targeting refuses a fallback that could navigate another profile.
- Agent execution steps retain bounded, whole verified receipts, allowing later steps to use opaque draft/review identifiers without inventing them. Receipt context is reset for a new task.
- System settings group startup, manual public release checks and diagnostics. The update checker uses no Relay account and opens a validated release page. It does not install an update automatically.

## Known remaining gaps

| Area | Remaining work or qualification |
|---|---|
| Autonomous Mac control | Broader native app and web form adapters, sustained multi-app tasks, unsupported controls, visual recovery, focus-conflict handling, and independent user/agent activity need more live qualification. Navigation and page reading can bind the foreground browser process, while generic app/control observations still refuse multiple processes with the same app identity. An accessible button or successful process exit alone does not prove the requested outcome. |
| General visual control | Window text fallback uses OCR. The image-inspection panel supports tool-free local vision, but it does not provide a general visual action/navigation loop. |
| Personal sources | Whole-account/background Mail and Notes ingestion, rich Messages bodies and attachments, live chat sync, and service-specific Gmail/Outlook/Slack/SiYuan/Granola adapters are not equivalent to selected-item capture, exports or an explicitly configured direct MCP server. |
| Knowledge and proactive plans | Generated Markdown highlights remain bounded per source. Cross-source people/project synthesis, ongoing consolidation and researched proactive plans remain narrower. Current suggestions are source-backed explicit TODO/ACTION extraction. |
| Final actions | Mail attachments and generic sends, booking, purchasing, CRM updates and publishing need dedicated adapters with identity, exact review and outcome receipts. Plain-text Mail submission does not establish these workflows. |
| Unattended preparation | The app scheduler and exact one-time privileged wake preview do not establish an automatically managed recurring wake/return-to-sleep helper. Physical closed-lid wake and power behavior remain unqualified. |
| New 2.8 quick actions | Relay has an explicit selected-text menu and a separate local result window. Dedicated global Summarize (⌘,) and Proofread (⌘.) shortcuts, direct spoken/typed quick-action routing, bounded offscreen document/PDF reads, combined text/window-image summaries, conversation-specific capture and verified same-chat continuation, native YouTube transcripts and multiple independent summary jobs remain gaps. Browser corrections currently support copying. Relay preserves ⌘. for Stop. See the pinned [Summarize design](https://github.com/Sentient-OS-Labs/sentient-os/blob/6214cc8b6bf30769f2af2272273931c41d14e744/Sentient%20OS%20macOS/Summarize/Documentation%20-%20Summarize.md) and [Proofread design](https://github.com/Sentient-OS-Labs/sentient-os/blob/6214cc8b6bf30769f2af2272273931c41d14e744/Sentient%20OS%20macOS/Proofread/Documentation%20-%20Proofread.md). |
| Voice and displays | Relay provides on-device dictation and modifier-key hold-to-dictate followed by explicit transcript review. The reference's notch press/hold-to-talk with release-to-send, integrated editable voice follow-ups, and independent entry handles on each external display remain different interactions. Relay's single panel currently prefers a notched display; position calculations alone do not establish per-display entry. See the pinned [notch and display design](https://github.com/Sentient-OS-Labs/sentient-os/blob/6214cc8b6bf30769f2af2272273931c41d14e744/Sentient%20OS%20macOS/Notch%20Magic/Documentation%20-%20Sidekick%20-%20Notch%20Window%20%26%20Visual.md). |
| Distribution | Developer ID signing, notarization, published signed archives, verified automatic installation/rollback and durable macOS permission identity across updates remain release gates. A valid ad hoc development signature does not establish distribution readiness. |
| Cross-device use | Loopback read-only MCP and encrypted portable note archives exist. Continuous phone/LAN/cloud synchronization and an iOS companion do not. |

## Verification of this batch

- The final default Swift run registered 652 tests in 113 suites: 624 executed without failures and 28 opt-in cases were skipped.
- Ten Python fixture/release tests and 149 repository/static scenario checks passed. These are not native desktop E2E tests.
- Real native fixtures verified the 11-case accessibility check, helper find/type/click readback, reviewed popup choices and refusals, path staging without choosing the file, and selected-text replacement with unchanged surrounding Unicode and refusal after target drift.
- Production browser navigation and reading passed in two disposable Chrome profiles: normal cold startup and a running process with no startup window. Exact selected URL, static fixture text, excluded editable values and owned-process cleanup passed. The independent loopback server recorded zero POST attempts and zero submissions across qualification.
- Real local Gemma CPU runs passed production chat/full-schema handling, exact write and Finder planning, long-context literal copying, and strict-JSON selected-text proofreading. The final updated-schema conversation gate took 44.041 seconds; the selected-text gate took 4.809 seconds. Synthetic execution hooks kept these model tests from changing apps or sending messages.
- The ad hoc development bundle passed strict deep signature verification, launched its regular workspace and completed the E4B model/tool-call readiness probe. System and Sources layouts were visually checked. Its live public update check reported no published stable release. The app reported missing Accessibility access and an unavailable login item in this build/location; neither permission nor startup registration was changed.

No test total should be interpreted as proof that every installed app, account, display, permission state or hardware configuration works. Live Mail delivery, service-account sync, system permission changes and privileged wake changes are not exercised by the synthetic qualification suite. Relay's own current build also needs its macOS grants; test-host access does not establish the app's permission state.

The reference's new summary and proofreading routes use hosted inference, and its new voice path uses ElevenLabs Scribe. These establish reference behavior, not permission for Relay to adopt the same hosted services. Local parity requires equivalent outcomes through an explicitly supported local path, with its own capability and quality qualification.
