# Relay parity follow-up — 6 November 2026

Reference: installed upstream project 2.7.6 (23). [Reference observations](referenceos-reference-2026-11-06.md) · [Earlier native acceptance](relay-parity-verification-2026-11-06.md). This follows the real macOS behaviors and keeps Relay’s default inference on the Mac.

| Capability | Delivered in this pass | Acceptance and boundary |
|---|---|---|
| Image and window inspection | Select a still file or one window using the macOS picker, preview it, and run tool-free local vision. Image and answer live in the panel. | Real E2B CPU and E4B GPU correctly distinguished opposite-color pixels through the production inference path. File validation refuses malformed data. In the signed release UI, a synthetic image with a red circle on a blue field returned “Red.” The system window picker opened; no window was selected in that release UI test. |
| Sidekick and writing | Optional Right Command single-tap opens Sidekick; Double Tap still drafts in the target editor. Optional separate local draft model and editable style suggestions from examples. | Gesture, package preference, style and existing real-editor checks passed. The rebuilt ad hoc bundle’s real global shortcut still depends on its Accessibility grant. |
| Notes and Mail | Capture exact selected items through each app’s read-only Apple Events API; ask about the selection in a private, tool-free session. | Fixtures verify scope, locked-note refusal, selection changes, cancellation and forgetting. Native OS preflight for Notes needed consent; Mail was not running. No live personal data or saved chat history was used. |
| Messages and WhatsApp | Read one selected conversation and time range from a standalone Messages database backup, or a selected WhatsApp text export. Ask privately in Relay. | A real synthetic SQLite fixture verified only the selected conversation and date range; both WhatsApp text formats and Unicode were tested. The signed app read a selected synthetic WhatsApp export and returned its exact code. Neither the chat data nor the image entered the QA conversation file. Native background account sync, rich-only Messages bodies and attachments are outside this path. |
| Generated knowledge | Incremental Markdown highlights for verified selected sources, exact provenance, stale source removal, editable copies and one-level folders. | Installed E2B CPU wrote and reloaded source-backed Markdown through the production AssistantStore. Folder and source revision tests passed. The signed app created a folder, saved an authored note into it and reopened that note in its reader. Generated content is bounded per pass; cross-source synthesis remains narrower than the reference. |
| Daily preparation and wake | Power- and sleep-aware scheduler; local-day reservation; exact one-time wake and cancel previews with native queue readback. | Live QA showed a Riyadh-time preview and confirmed no system wake was scheduled. Applying the command is separate and privileged. Physical wake, closed-lid wake and automatic return to sleep remain unverified. [Apple’s scheduling instructions](https://support.apple.com/en-gb/guide/mac-help/-mchl40376151/mac) |
| Local sharing | Explicitly selected note revisions, short-lived bearer token, and read-only MCP over IPv4 loopback. | Kernel and real-client tests confirmed 127.0.0.1-only bind, successful authorized reads, 401 without auth, revocation on note change and a closed port after Stop. No LAN endpoint. |
| Portable sharing | Authenticated encrypted archive of selected authored notes, fresh recovery code, and read-only import preview. | Exact Unicode round trip, mode 0600, ciphertext-only file, and wrong-code, truncation and tampering rejection passed. In the signed app, one selected note was written as a 204-byte private ciphertext file and opened with its recovery code in a read-only panel. No automatic upload or hosted sharing service. |
| Direct MCP | Explicit HTTPS or literal loopback connection, modern discovery and legacy compatibility, exact read review, and optional local questions about the returned text. | Real loopback modern/legacy, pagination, SSE, Unicode and redirect isolation passed. No real service accounts were connected. A server’s read-only tool label is not proof of its remote behavior. |

The Swift suite registered 521 tests in 92 suites. It executed 505 without failures; 16 opt-in cases were skipped in that run and selected native cases ran separately. Ten Python fixture/release checks and 149 repository scenario checks passed. The [earlier verification](relay-parity-verification-2026-11-06.md) retains the Finder, Calculator, browser, accessibility, screen-capture and cancellation acceptance evidence.

The final app passed strict deep code-signature verification, reopened in the regular Relay workspace, and reported its existing missing Accessibility grant without changing it.

Full parity is still open for background native account sync across services, equivalent rich message and attachment ingestion, hosted providers and cross-device cloud sharing, autonomous overnight wake and return to sleep on qualified hardware, and reviewed final sends/transactions. The local development bundle does not establish Developer ID distribution, notarization or stable macOS grants across updates.
