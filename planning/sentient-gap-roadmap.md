# Relay feature roadmap and release test plan

Updated 30 October 2026. Execution backlog for the user's request to build the missing personal-assistant experience, with local inference, optional task networking, white readable text, independent critique, and parallel implementation. This document does not certify universal task completion or feature parity.

Reference: [Sentient advertised features](https://sentient-os.ai/), inspected 30 October 2026. Its advertised categories include computer use, contextual reply drafting, personal knowledge, proactive preparation, local inference, and team integrations. Its offline mode already exists; Relay must compete on a specific, measured experience. Advertising is not an independent benchmark of the reference product.

## Product contract

A user describes an outcome in one conversation. Relay discovers relevant information and apps, acts within authorized scope, checks observable results, preserves partial work and reports concrete limits. No user-selected workflow templates are required. All planning, extraction, OCR, retrieval and generation remain local. Internet is used only for explicit downloads/updates or user-requested online tasks. No hosted inference or silent fallback.

Implement missing capabilities in dependency order. Proactive features are opt-in and initially prepare drafts only; nothing is enabled in the background because a feature was implemented. Source permissions, knowledge retention and action authority remain separate. Sending, publishing, destructive operations and final submissions require separately qualified destination/content review. Autonomous financial checkout and account-security administration remain excluded; travel/shopping features can research and prepare choices without paying.

Status terms: **existing** means code exists with documented evidence; **implementing** means active changes without release sign-off; **pending** means not delivered; **blocked** names an external prerequisite. Every task needs a separate implementation and verification status. Tests against mocks do not certify live app behavior.

## Milestones and parallel ownership

1. **Useful local alpha:** R01–07, R10–11, K01–03, Q01–02, X01–03. Ship only a declared supported envelope. First practical workflows: find/open a document, inspect/search approved knowledge, prepare a sourced answer, navigate/search in a chosen browser and leave forms unsubmitted.
2. **Contextual daily assistant:** R08–09/R12–14, K04–09, Q03–06. Add capabilities one at a time behind per-feature qualification.
3. **Proactive preparation:** P01–05, after useful-task reliability and context correctness. Opt-in and draft-only first.
4. **Public distribution:** X04–06 and the alpha release gate. External signing/account requirements remain concrete blockers.
5. **Broader platforms/teams:** X07–10 with separate product and platform validation.

Workstreams: browser/control integration; local knowledge/models; native product/UI; independent QA/critique. Only one executor may control the desktop at a time. Implementation agents own separate files; integration and public claims remain the root's responsibility. Antigravity is used for an independent read-only review, not unreviewed concurrent source edits.

Effort is not a calendar promise: each milestone must pass its exit gate before the next depends on it. Hardware, protected-source access, model vision and signing are feasibility/external gates.

## Test plan and corner cases

### Shared harness and reporting

Keep deterministic controller tests separate from real-model planning and live UI execution. Use synthetic files, a local multi-field form fixture and disposable media. Every case records starting state, request, observed controls/source scope, dispatched actions, exact independent oracle and final state. Report pass/fail/blocked/not run; skipped tests are not passes. Maintain held-out wording/app-state variations. Never count a long tool list as completion of a requested mutation.

| Area | Required edge cases | Pass criterion |
|---|---|---|
| Intent and completion | Direct question, action request, vague app, missing essential fact, multi-step objective, premature 'done', unnecessary confirmation, steering changes target | Answer-only remains side-effect free; necessary supported steps proceed; unresolved conditions remain visible. |
| Browser | Missing browser, unsupported names, no windows, multiple tabs/windows, existing edited page, lost focus before each fixed key, redirects, stale AXURL, loading/blank page, modal/security/auth prompt, Unicode and reserved URL characters | Preserve previous page, no input to wrong field/app, exact destination evidence or uncertain status; no auth/security bypass. |
| Forms | Duplicate/missing labels, reordered/offscreen fields, checkbox/select/radio, multiline/emoji/Arabic, validation error, stale DOM/AX, cross-origin iframe, upload, login expiry, confirmation page | Exact fields and untouched controls independently checked; ambiguity blocks guessing; no final submission without qualified review. |
| Desktop | App crash, pid reuse, same window title, switch Spaces/display, disabled/canvas/secure controls, timeout after actual action, accessibility revocation | Fresh identity/focus/enablement, uncertain effects reconciled, no duplicate click or leaked secure text. |
| Knowledge | No sources, empty/invalid/corrupt files, deleted/replaced file, same size/mtime changed content, revoked grant, symlink escape/loop, hidden tree, very large corpus, non-UTF8, scanned/locked PDF, zero hits | Only in-scope current sources retrieved; bounded resource use and truthful unsupported/truncated states; revoke purges retained index. |
| Knowledge persistence | Damaged JSON, duplicate paths, malicious relative paths, interrupted save, changed format/version, clear/export while indexing | No unsafe restore, no partial overwrite of valid state, no repopulation after cancel/revoke/clear. |
| Model provisioning | HTTP errors/HTML body, incomplete/oversized response, redirect, hash mismatch, disk full, permission denied, cancellation at transfer/hash/install, existing unknown file, retry/relaunch | Never install unverified data or overwrite unknown model; progress is real; no fake resumability. |
| Local inference | Missing/corrupt model, unsupported CPU/GPU, low memory, long context, output schema errors, model says 'done' without evidence, timeout, cancellation during load/generation | Helpful component-specific failure, no hosted fallback, no dispatch from malformed/stale output. |
| Shortcut/context | Conflict, repeat enable/disable, another app focused, secure selection, no selection, enormous Unicode selection, modal/auth, app changes during capture | Opt-in only; no background key/text collection, proper source identity, safe limit/refusal, no auto send. |
| Proactive | Off by default, timezone/DST, sleep/missed schedule, battery/offline, duplicate run, revoked sources, stale reminder, dismissal, conflicting user task | No unauthorized wake/network/action; deduplicated bounded draft preparation with evidence and recovery. |
| Policy | Changed payload/recipient/site after approval, decline, stop while reviewing, external text asks to widen permissions/send secrets | Review invalidated on material change; external content never becomes authority; no equivalent retry after decline. |
| Offline | Network unavailable before startup/during online request, denied host, model missing, local source search | Local supported work remains usable with provisioned assets; online dependency accurately disclosed; no model egress. |
| UI | 800×620 and larger, long localized text, enlarged text, white contrast, keyboard-only/tab order, VoiceOver, reduced motion, errors+loading+six-line draft, new-step scroll reset | No unreachable controls, misleading ready badge, hidden active Stop, false success or essential low-contrast text. |
| Release | Clean Mac install, update from previous version, TCC stale entry, uninstall, signature/notarization validation, rollback | Stable identity and recoverable updates; no silent security setting changes or personal-data deletion. |

### Proposed release gate

Measured targets remain targets: at least85% verified completion and75% without avoidable intervention on a declared held-out supported suite; zero observed false completion, unauthorized consequential action or post-Stop dispatch; Stop acknowledgment within1second; no out-of-memory termination on declared hardware. Publish denominator, model/hardware/app versions, failures and unsupported cases. One successful demo or passing unit suite does not satisfy this gate.
