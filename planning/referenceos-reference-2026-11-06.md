## Relay gaps the reference supports testing

- **Desktop recovery and screenshot qualification.** Relay already bundles an isolated native fixture with AX inspection, Unicode readback, independently verified clicking, stale and disabled control rejection, changed-review rejection, and Stop invalidation. Its existing check does not qualify screen capture. The next comparable check would bind a uniquely marked synthetic window to a decoded screenshot and report AX and screen capture readiness separately. If there is no supported screenshot path or grant, surface that as an independent state. A screenshot permission checkbox by itself is not a passed capture.
- **Knowledge.** The staged Relay notes workflow can create and edit private Markdown, filter displayed titles, read notes in the existing graph and export a verified source snapshot with path, time, coverage and content hash. It is a narrower acceptance slice than Reference's visible folder creation, full note search and model-assisted generation from a multi-source knowledge vault. Separate local notes and sources should remain distinguishable. Source revocation must prevent fresh exports from an old snapshot.
- **Quick access and drafting.** A successful launch/shortcut test cannot stand in for a focused-field draft. Qualification requires a disposable editable field, correct original target, unsent text readback, a single insertion, no change after focus loss and refusal for a secure field. The installed reference only demonstrated the gated instructions today.
- **Personal connectors and suggestions.** A connector row, browser visit, or login state cannot stand in for scoped readback. Each supported source needs explicit selected scope, a known fixture, freshness/revocation behavior and an answer that cites matching evidence. Hosted-only providers and cloud MCP require a separate product decision from Relay's local-inference default. Overnight claims require a real supported sleep/wake run and no missed or duplicate preparation.
- **Arbitrary app workflows.** Keep action delivery, observed results and the final user-facing claim separate. Repeat the three public/synthetic reference scenarios on the current Relay build and retain evidence. Cover ambiguous windows, unsupported controls, cancellation, Unicode entry, and click/readback in disposable fixtures before expanding any parity claim.

No settings, source selections, personal-analysis state, accounts, permissions, external messages, or existing data were changed. The live changes were limited to view navigation and starting Reference's own isolated computer-use fixture.
